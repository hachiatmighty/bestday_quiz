# Worked example: the goal-archetype quiz

This is Bestday's first quiz, live at bestday.ai/quiz. Use it to see the playbook's decisions in practice, or when you're changing this quiz itself. A new quiz can reuse its code and patterns, but shouldn't copy its topic, results or copy.

## Where it lives

| What | Where |
| --- | --- |
| Source (static Astro site) | `hachiatmighty/bestday_quiz`. As of October 2026 the live build came from the `claude/manifesto-landing` branch (PR #1, not yet merged). The default branch is older. Check which commit the last release PR names, and branch from that. |
| Live build | `public/quiz` in `kayakinwunmi/bestday-ai-landing-page`. It's generated, so never edit it by hand. |
| Site header, footer, page gutters and capture endpoint | Added to the build by `scripts/apply-quiz-overrides.mjs` in the website repo. A change to the website header needs a matching edit there. |
| Sent emails | The `quizCaptureWeb` Cloud Function: Firebase project `getbestday-88ef7`, staging `bestday-staging`. It isn't in either repo. `src/data/emails.ts` only drives the previews. |
| Analytics | Mixpanel project "Bestday Quiz" (4068985), EU. |
| Routes | `/quiz`, `/quiz/r/:slug` (share pages) and `/quiz/start` (email redirect to Branch) each have rewrites in the website's `vercel.json`, above the SPA catch-all. |

## How its pieces map to the playbook

- **Data** (results, questions, pairings, landing lines): `src/data/quiz.ts`. Email preview copy: `src/data/emails.ts`. Branch links: `src/lib/signup.ts`.
- **Screens:** all in `src/components/QuizApp.astro`:
  - landing, from `LandingPage.astro`;
  - the context question;
  - "Before you start";
  - 20 statements;
  - loading;
  - teaser;
  - email gate;
  - full result;
  - "What happens next".
- **Scoring:** `src/lib/scoring.mjs`. It keeps its own copy of the result order. Tie-breaks are, in order: the most "That's me" answers, the highest score on cost statements, then a stable hash of the answers.
- **Analytics:** `src/lib/analytics.ts`. Capture: `src/lib/capture.ts`.
- **Cards and link-preview images:** `scripts/generate-social-assets.mjs`.
- **Counts hard-coded for 5 results and 20 statements:**
  - `stepCount = 22`;
  - the "of 20" progress label;
  - the `.fit-types` grid;
  - the landing figure row;
  - the card slots in the shared link-preview image;
  - about seven test files.
- **Tests:** `npm test`. Some tests read the built `dist/`, so run `npm run build` first. `tests/result-copy.test.mjs` pins the result copy to `docs/copy/RESULT_COPY_V4.md`, and rejects em dashes and "may".

## Shipping it

1. Work on a branch in the quiz repo, then run `npm run build` and `npm test`.
2. Run:
   ```sh
   PUBLIC_MIXPANEL_TOKEN=<Bestday Quiz token> scripts/ship-quiz.sh <quiz-repo> <website-repo>
   ```
   The script is in this skill. It:
   - builds with the live settings;
   - runs the tests;
   - removes the internal email previews;
   - copies the build into `public/quiz`;
   - runs the override script;
   - lists the app links;
   - fails if a store URL or the Mixpanel token is missing.

   Get the token from Mixpanel's `Get-Project-Token` (project 4068985).
3. Check it locally: run `npx vite build && npx vite preview --host 127.0.0.1` in the website repo. Without `--host`, vite can fail with EAFNOSUPPORT. Then use Playwright with Chromium at `/opt/pw-browsers/chromium` to take screenshots at 390px and 1440px and to intercept Mixpanel requests.
4. Make a new branch from `develop` in the website repo, commit, push, and open a PR into `develop`. Then open a release PR from `develop` into `main`.

## Gotchas that have bitten before

- **Mixpanel token:** a build with an empty `PUBLIC_MIXPANEL_TOKEN` silently tracks nothing. That happened from launch until 8 October 2026.
- **Unsubscribe link:** the email footer links to `bestday.ai/unsubscribe`, which 404s. It's still unresolved.
- **CSS animation:** the Lightning CSS minifier turns an `animation:` shorthand with no name into `animation:none`. Use the longhand properties.
- **Astro styles:** Astro scopes component CSS, so classes generated by script need `:global(...)`.
- **Hidden elements:** a `display` rule can override `[hidden]`. Add `[hidden]{display:none}`.
- **Jump links:** the landing page's jump links are buttons, not `#anchors`, because a hash change fires `popstate`, which the quiz uses for its steps.
- **Killing preview servers:** `pkill -f "vite preview"` can kill the shell that runs it. Stop the server in its own command.
- **Git fetch:** if `git fetch` only tracks `main`, add a fetch refspec for your branch or push with `-u`.
- **Branch links:** you can't open app.link from the cloud sandbox. Ask whoever owns Branch to confirm desktop fallbacks.
- **`claude-review` check:** it fails with `401 OAuth access token has expired` until the repo secret is renewed. Post one comment saying so, and don't try to fix it in code.
